# Maintaining Mayfly

Read `AGENTS.md` in the repo root first; it lists the invariants. This skill is
the "how do I…" for operations. All commands assume the repo root unless noted.

## Preconditions

- Elixir ≥ 1.18, OTP ≥ 27 locally (`mise use erlang@27.3.4.18 elixir@1.18.4-otp-27`
  gives a toolchain that matches the published 27 layer).
- `gh` authenticated as the repo owner; AWS profiles `mayfly-admin` and
  `elixir-playground` configured. Container CLI: `docker` or `finch`.
- Before any release or publish: `mix format --check-formatted`,
  `MIX_ENV=test mix compile --warnings-as-errors`, `mix test`,
  `MIX_ENV=test mix dialyzer`, `mix docs` – all clean.

## Release a library version

1. Bump `@version` in `mix.exs`; move CHANGELOG "Unreleased"/rc notes under
   `## [x.y.z] - YYYY-MM-DD`; update the version badge in `README.md` and in
   `skills/mayfly-elixir-lambda/SKILL.md` metadata.
2. Regenerate docs into the website (see below) so the published docs match.
3. `git commit -am "Release vX.Y.Z" && git tag vX.Y.Z && git push && git push --tags`.
4. `publish.yml` runs: verifies tag == version, checks, `mix hex.publish`,
   GitHub release. First time: `gh secret set HEX_API_KEY` with a key from
   `mix hex.user key generate --permission api:write`.
5. Verify: https://hex.pm/packages/mayfly and `gh release view vX.Y.Z`.

## Layers

### Routine (nothing to do)
`layers.yml` runs Mondays. It builds the newest patch of each configured OTP
major, publishes to all regions, updates the `layers` release and the website
catalog. Check `gh run list --workflow layers.yml` occasionally.

### Force a run / publish a specific OTP
```bash
gh workflow run layers.yml -f public=true                       # latest patches
gh workflow run layers.yml -f otp_versions="27.3.4.17 27.3.4.18" # explicit
gh run watch                                                     # ~25 min
```

### Add an OTP major
```bash
gh variable set LAYERS_OTP_MAJORS --body "27 28 29 30"
gh workflow run layers.yml
```
Check which Elixir versions have a precompiled build for the new major
(`curl -sI https://builds.hex.pm/builds/elixir/v<elixir>-otp-<major>.zip`) and
record the pairing in `guides/layers.md`. Currently published: 27, 28, 29.
Then verify the new major on the playground (see "Deploy a test function").
Update the README "Requirements" row and `guides/layers.md` if the supported
range changes.

### Add a region
```bash
gh variable get LAYERS_REGIONS            # current list
gh variable set LAYERS_REGIONS --body "<current list> eu-south-1"
gh workflow run layers.yml                # idempotent: only the new region publishes
```
Also add the region to `regionNames` in `mayfly_website/layers.js`.

### Local build/publish (emergency)
```bash
layer/build.sh --otp 27.3.4.18 --arch arm64     # docker or finch; arm64 native on Apple Silicon
AWS_PROFILE=mayfly-admin layer/publish.sh --region eu-central-1 --arch arm64 --public --skip-existing
```
`layer/dist/arns.json` is what the website consumes; merge it into
`mayfly_website/data/layers.json` if you publish manually.

### Rules
- Never delete a layer version. Users pin ARNs.
- Publish public layers only from mayfly-admin (651236577491).
- The publisher role (`layer/publisher-role.yml`, stack `mayfly-layers-publisher`)
  may only touch `mayfly-erlang-*` layers. Re-deploy with
  `AWS_PROFILE=mayfly-admin aws cloudformation deploy --stack-name mayfly-layers-publisher --template-file layer/publisher-role.yml --capabilities CAPABILITY_NAMED_IAM --parameter-overrides GitHubRepo=bmalum/mayfly CreateOidcProvider=false`.

## Website and docs (`../mayfly_website`)

- Landing page: `src/index.html` (Tailwind classes; `src/input.css` compiles
  to `dist/output.css`). Layer catalog: generated by `layers.js` from
  `data/layers.json`. Sitemap: `sitemap.js`. Redirects/headers: `src/_redirects`,
  `src/_headers` (Cloudflare Pages; do not add `/docs/index.html` rewrites,
  Pages' pretty URLs make them loop).
- Docs: generated from this repo, committed into the website repo:
  ```bash
  mix docs -o ../mayfly_website/docs
  cd ../mayfly_website && npm run build && git add -A && git commit -m "docs: regenerate" && git push
  ```
  `docs/dist/` must stay tracked (the `.gitignore` rule is `/dist/`, anchored).
- Deploy: push to `main`; Cloudflare Pages builds `npm run build` and serves
  `dist/`. Live in ~1 minute. Verify `curl -sI https://elixir-aws-lambda.dev/docs/`
  returns 200 and `/layers/27/arm64/eu-central-1.json` returns JSON.
- Links inside the site use extension-less docs URLs (`/docs/streaming`, not
  `.html`).

## Deploy a test function (playground)

```bash
cd /tmp && mix new demo && cd demo
# mix.exs: deps [{:mayfly, path: "/path/to/mayfly"}], releases lambda with the four
# Mayfly.Release steps and mayfly: [handler: Demo.Handler, layer: true]
mix lambda.invoke Demo.Handler '{"a":1}'       # local first
mix lambda.doctor                              # prints the public layer ARN for your OTP/region
MIX_ENV=prod mix release lambda
AWS_PROFILE=elixir-playground aws lambda create-function --function-name mayfly-test \
  --runtime provided.al2023 --architectures arm64 --handler Demo.Handler \
  --layers <ARN from doctor> --zip-file fileb://_build/prod/rel/lambda/lambda.zip \
  --role arn:aws:iam::537124966503:role/mayfly-playground-lambda-role --timeout 30 --memory-size 512 \
  --logging-config LogFormat=JSON
```
Streaming: `aws lambda create-function-url-config --auth-type AWS_IAM --invoke-mode RESPONSE_STREAM`
(public `NONE` URLs are blocked in this account) or boto3 `invoke_with_response_stream`.
Managed Instances: create a capacity provider (m7g.large, arm64, `MaxVCpuCount: 16`,
no scaling policy), function with `--memory-size 2048` and
`--capacity-provider-config`, invoke the published version; **delete the
capacity provider afterwards**, it bills EC2.

## Playbooks

| Symptom | Cause | Fix |
|---|---|---|
| Layers workflow: `ssl` smoke test fails | OTP built without crypto (OpenSSL linkage) | check `lambda.Dockerfile` `otp` stage; must link dynamically, never `--disable-dynamic-ssl-lib` |
| Layers workflow: `AccessDenied` on publish | OIDC trust or role policy | stack `mayfly-layers-publisher` in mayfly-admin; trust is `repo:bmalum/mayfly:ref:refs/heads/main` |
| Website catalog not updated after a run | deploy key | `gh secret list` shows `WEBSITE_DEPLOY_KEY`; `gh repo deploy-key list --repo bmalum/mayfly_website` shows a write key |
| Docs pages unstyled / 404 on `docs/dist/*` | assets not committed | `git ls-files docs/dist` in website repo must list js/css |
| `/docs` redirect loop | a `_redirects` rule targets `index.html` | remove it; Pages handles directory index itself |
| User: `release was built for ERTS X but layer provides Y` | toolchain/layer OTP mismatch | `mix lambda.doctor`; `mise use erlang@<layer otp>` |
| User: `Runtime.NoSuchHandler` | Handler setting not a module in the release | module name, `use Mayfly.Handler`, release includes the app |
| Consumer zip unexpectedly large | something under `priv/` | only `priv/rel/` may exist in this repo |
| Mix task needs `:inets`/`:ssl` | Mix prunes code paths | `Code.prepend_path` + `Application.load` as in `lambda.doctor` |
